# Ontology v0.1

The ontology starts deliberately small. Concepts should become shared primitives only when they have meaning beyond one product's UI or database.

## Actors

### Actor

An entity capable of participating in organisational activity.

Initial types: person, organisation, team, agent.

### Relationship

A meaningful connection between two actors. Relationships are first-class because they change, carry evidence, accumulate history and affect attention.

## Perception and meaning

### Observation

Something perceived or recorded without requiring it to be significant.

### Signal

A potentially meaningful pattern, change or occurrence derived from one or more sources.

### Evidence

Something that supports, contradicts or contextualises another object.

## Direction and judgement

### Intention

Something an actor wants to be true.

### Assumption

A proposition being treated as true despite uncertainty.

### Decision

A choice that has been made, ideally retaining reasoning, evidence, alternatives and assumptions.

## Action

### Commitment

An agreement or promise that something will happen. A commitment is not the same as a task.

### Action

Something to do or something that was done.

### Practice

A reusable description of how work is performed, including purpose, roles, tools, constraints and evaluation.

## Learning and change

### Outcome

Something that resulted from organisational activity.

### Change

A difference between organisational states. Many Changes may be derived from event history rather than manually authored.

## Context is graph-shaped

There is no universal Context object containing arbitrary application data.

Context emerges from relevant nearby organisational objects for a specific purpose. That purpose-bound subset is transported as a Context Packet.
